Underneath every channel, invoice and onion, Lightning <Term id="node">nodes</Term> exchange plain messages: a few bytes with a fixed layout, sent over an encrypted link (next lesson).

## A message, byte by byte

Every message starts with a **2-byte type**, big-endian, then the fields for that type. The first message on every connection is `init`, type 16:

```text
0010          type = 16 (init)
0000          gflen = 0       (length of the old "global features")
0003          flen  = 3       (length of the features field)
0a69a2        features        (a bit field)
0120 0606…    TLV stream      (optional extra records)
```

## Feature bits: "it's OK to be odd"

Each feature has a pair of bits. The **even** bit means "I require this; disconnect if you don't support it". The **odd** bit means "I support this, but it's optional". Unknown odd bits are ignored and unknown even bits end the connection. New features can roll out gradually without splitting the network.

## TLV: type, length, value

After the fixed fields, a message can carry a **TLV stream**: records of `type | length | value`. The same rule applies: unknown odd types are skipped, unknown even types are an error. This is how the protocol grows; older nodes simply skip records they don't understand.
