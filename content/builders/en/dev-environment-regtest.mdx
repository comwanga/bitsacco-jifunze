<Term id="regtest" /> is a private Bitcoin network that only you can see. Mining is instant, coins are free, and mistakes cost nothing. Every lesson in this path uses it as your lab.

## Step 1: Three networks, one program

The same Bitcoin Core program can join three kinds of network. Think of a driving school:

- **Mainnet** is the highway: real traffic, real money, real consequences. You don't learn here.
- **Testnet and signet** are a shared practice track. Other learners are on it too, and you wait for its blocks like everyone else.
- **Regtest** is your own empty car park. Nobody else is there, and a block appears the moment you ask for one.

Two programs do the work. `bitcoind` is the node itself, running in the background, and `bitcoin-cli` is how you talk to it. Everything the node knows lives in its data directory, so deleting that folder gives you a brand-new chain.

One rule will surprise you in Step 3: a miner's reward can't be spent until 100 more blocks are built on top of it. Bitcoin calls this **coinbase maturity**.

**Done when:** you can say, in your own words, why your first test coins only become spendable after 101 blocks.

## Step 2: Install and start a node

Install Bitcoin Core from the official download page, or use a Docker image you trust. Then:

```bash
bitcoind -regtest -daemon -fallbackfee=0.0001
bitcoin-cli -regtest getblockchaininfo
```

**Expected:** JSON with `"chain": "regtest"` and `"blocks": 0`.

<Callout type="tip" title="Save typing">
Add `alias bcli="bitcoin-cli -regtest"` to your shell profile. The rest of this path writes the full command so it works for everyone.
</Callout>

**Done when:** the node answers `getblockchaininfo`.

## Step 3: Mine, fund and check

```bash
bitcoin-cli -regtest createwallet "alice"
ADDR=$(bitcoin-cli -regtest -rpcwallet=alice getnewaddress)
bitcoin-cli -regtest generatetoaddress 101 "$ADDR"
bitcoin-cli -regtest -rpcwallet=alice getbalance
```

**Expected:** a balance of `50.00000000`. You mined 101 <Term id="block">blocks</Term>, but only the first block's reward has matured.

Try `generatetoaddress 1` again and check the balance. Can you predict the new number before you look?

**Done when:** you can explain why the balance after 101 blocks is 50, not 5,050.

## Step 4: Reset

```bash
bitcoin-cli -regtest stop
rm -rf ~/.bitcoin/regtest   # on macOS: ~/Library/Application Support/Bitcoin/regtest
```

Starting from a clean datadir makes experiments repeatable, which is exactly what you want for automated tests later.

## Producing, relaying and validating are different jobs

Your regtest miner proposes blocks in a deliberately easy test network. A full node independently checks consensus rules; hearing a block from a peer or a miner does not make it valid. Relay policy also governs which unconfirmed transactions a node chooses to keep or forward, and is distinct from block validity. Different mempools do not by themselves establish a consensus split.

An archival full node retains historical blocks. A pruned full node can still validate while discarding older block data after verification. Keeping every historical byte and checking the rules are different properties. Peer connectivity affects which data a node sees and when; it does not grant a peer permission to create invalid coins.

For the discussion below, describe a controlled two-node regtest experiment: what would each node observe if one stops receiving blocks, and how would you distinguish delayed information from invalid data? Do not infer mainnet propagation, mining incentives or adversarial resistance from one isolated regtest miner.
