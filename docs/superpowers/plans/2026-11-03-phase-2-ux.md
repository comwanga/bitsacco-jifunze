# UX Phase 2 implementation plan

2026-11-03 · approved implementation plan

**Design:** [Learning trees and practice simulations](../specs/2026-11-03-phase-2-ux-design.md).

**Goal:** Native, accessible learning trees for the existing three paths, plus two small browser-only simulations: UTXO transactions and Lightning channel balances. The website remains a static export.

**Base:** Updated main at verified Phase 1 merge `1a1ad0d291e949c1a70748022e9ac36149977a15`. Implementation branch: `feat/phase-2-ux`. The maintainer authorized all seven tasks and the two specified simulations. Do not push or create a PR without explicit authorization.

## Rules carried through every task

- Reuse lesson order, prerequisites, quizzes and progress rather than maintaining parallel copies. All lessons remain open regardless of prerequisites.
- No new runtime dependencies; use native HTML, CSS and small React islands. Preserve CSP and the existing live lab behaviour.
- All new strings ship in `sw` and `en`. Shared navigation labels use `lib/i18n.ts`; simulation copy uses a typed feature dictionary and parity test so existing bundles remain small.
- Simulations use safe integer sats, pure transitions and temporary state. They do not store progress, complete a lesson or connect to any node.
- Every route has useful initial HTML and correct language switching. Tree links work with JavaScript disabled; simulations retain a worked example.
- Signed commits, no co-author trailers. Preserve the user's untracked `image.png`.
- Add meaningful model tests before implementation; record failing and passing results. Run affected browser checks after a production build. Use the final full suite once the integrated feature is ready.

## Final review focus

1. A tree has a lesson with two prerequisites, a long translated title or no progress storage. Every lesson remains readable and reachable.
2. A learner enters a fractional amount, repeats a spent coin or attempts an oversized channel payment. Feedback is specific and the state stays valid.
3. A learner completes a simulation on a lesson with live exercises. No lesson completion or lab pass is fabricated.
4. A page is opened without JavaScript or while an interactive chunk cannot load. Explanations and lesson links remain usable.
5. The initial page meets its budget but the deferred chunk is oversized. The activated browser budget must catch it.

No dates or estimates are promised. Keep unresolved product choices and measured failures in the ledger rather than silently expanding this two-simulation scope.
